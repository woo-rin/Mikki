# 모의주식게임 백엔드 API 명세

작성일: 2026-09-14 · 대상 커밋: `c016a7f` · 서버: FastAPI (`backend/app/main.py`)

> **이 문서는 두 부로 나뉜다.**
> **1부(§00~§08)** 는 **지금 돌아가는 계약**이다 — 실제 서버 응답을 캡처했고 테스트 192개가 지킨다.
> **2부(§10~§13)** 는 **아직 구현되지 않은 설계**다 — AI 참가자, 거래량, 현금 기준 목표.
> 프론트는 1부에만 의존해 만들 수 있고, 2부는 착수 전에 읽어야 할 예고다.

이 문서는 **실제 서버 응답을 캡처해** 작성했다. 코드를 읽고 추정한 것이 아니다.

## 0. 시작하기

```bash
cd backend
./run.sh              # 포트 7999 로 고정
```

또는 직접:

```bash
cd backend
.venv/bin/uvicorn app.main:app --port 7999
```

> **포트는 7999 다.** `--port` 를 빠뜨리면 uvicorn 기본값인 8000 으로 조용히 떠서
> 프론트가 엉뚱한 곳을 두드리게 된다. `run.sh` 를 쓰면 그럴 일이 없다.

- **작업 디렉터리는 반드시 `backend/`** 다. `main.py` 의 정적 파일 마운트가 cwd 상대 경로다.
- `ANTHROPIC_API_KEY` 가 있으면 뉴스와 해설이 Claude 문장, 없으면 로컬 템플릿이다.
  **어느 쪽이든 API 모양은 동일**하고, 응답의 `offline` 플래그로 구분한다.
- 인증 없음. 세션은 `session_id` 문자열 하나로 식별한다.
- 세션은 서버 메모리에만 있다. **서버를 재시작하면 모든 게임이 사라진다**(404).

## 1. 반드시 먼저 이해할 것 — 시장은 폴링이 굴린다

서버에는 타이머가 없다. **`GET /api/state` 요청이 도착할 때 비로소 시장이 흐른다.**
서버는 세션 시작 시각과 현재 시각의 차이로 경과 tick 을 계산하고, 그만큼 가격을 진행시킨다.

프론트가 알아야 할 결과 세 가지:

| | |
|---|---|
| 폴링을 멈추면 | 시장도 멈춘 것처럼 보이지만, 다시 폴링하면 그동안의 tick 이 한꺼번에 계산된다 |
| 폴링 간격이 달라도 | 가격은 동일하다. 500ms 폴링과 5초 폴링이 같은 결과를 낸다 |
| 탭을 비웠다 돌아오면 | 그 사이 뜬 뉴스는 램프가 이미 끝나 있다. 기회를 놓친 것이 맞는 동작이다 |

**권장 폴링 간격은 500ms.** 1 tick = 1초지만, **시세는 5초에 한 번만 앞으로 간다** —
`tick` 은 언제나 5의 배수이고 같은 5초 창 안에서는 몇 번을 폴링해도 값이 같다.

tick 단위를 5초로 바꾸지 않은 이유가 있다. 램프(15~40초)·AI 반응(1~9초)·앵커 반감기가
전부 tick 으로 쓰여 있어서, 단위를 바꾸면 그것들이 함께 5배 길어져 밸런스를 다시 잡아야
한다. 관측 시점만 끊으면 보이는 결과는 같고 의미는 하나도 안 바뀐다.

## 2. 공통 규약

### 오류 본문

FastAPI 의 `HTTPException` 을 쓰므로 **본문이 `detail` 아래 중첩된다.** 프론트는 이 모양을 파싱한다:

```json
{ "detail": { "code": "bad_quantity", "message": "수량은 1주 이상이어야 합니다." } }
```

`message` 는 사용자에게 그대로 보여도 되는 한국어 문장이다.

**예외 하나**: 자료형이 틀린 요청(예: `qty: 1.5`)은 FastAPI 의 검증 계층에서 잘려
`422` 와 함께 **전혀 다른 모양**(`detail` 이 배열)을 돌려준다. 정수 스테퍼를 쓰면 발생하지 않는다.

### 숫자

- **돈과 수량은 전부 정수**다. 현금·평가액·체결금액·수수료 모두 원 단위 `int`.
- 반올림은 전 구간 **내림**이다.
- 유일한 실수(float)는 `change_pct` 뿐이고, 표시 전용이라 어떤 판정에도 쓰이지 않는다.

### 종목 심볼

| 심볼 | 이름 | 섹터 | 시작가 |
|---|---|---|---|
| `hanbit` | 한빛솔리드 | 반도체 | 82,000 |
| `geno` | 제노셀 | 바이오 | 45,000 |
| `sungjin` | 성진셀즈 | 2차전지 | 61,000 |
| `pixel` | 픽셀로그 | 게임 | 33,000 |
| `taesan` | 태산건영 | 건설 | 18,500 |
| `arawings` | 아라윙스 | 항공 | 24,000 |

전부 가상 기업이다. 실재하는 상장사와 무관하다.

## 3. 엔드포인트

### `POST /api/game` — 새 게임

요청 본문은 **선택**이다. 안 보내면 AI 5명으로 시작한다.

```json
{ "ai_count": 5 }
```

`1`~`9`. 범위 밖이면 `400 bad_ai_count`.

> AI 수는 난이도 다이얼이다. 명단 위에서부터 채우므로 5명이면 고수 2 와 중간 3 이고,
> 9로 올리면 잘 낚이는 참가자들이 들어와 체결 피드가 시끄러워진다. **거래량이 늘어
> 주문 흐름이 가격에 더 크게 작용한다.**

응답 `200`: **아래 §4 의 상태 스냅샷과 동일한 모양.** 시작 시점이므로 `tick: 0`,
`cash: 1000000`, `target: 3000000`, `analyses_left: 5`.

> **주의**: 시작 직후 `news` 는 **빈 배열**이다. 뉴스는 12~18초 간격으로 등장하므로
> tick 0 에 보일 기사가 없는 것이 정상이다. `news_total` 은 이미 20 이지만 아직 아무것도
> 공개되지 않은 상태다. 프론트는 빈 피드를 오류로 다루면 안 된다.

응답의 `session_id` 를 저장해 이후 모든 요청에 넣는다.

### `POST /api/trade` — 시장가 매매

```json
{ "session_id": "…", "symbol": "geno", "side": "buy", "qty": 2 }
```

`side` 는 `"buy"` 또는 `"sell"`. 지정가·공매도·레버리지는 없다.

응답 `200` — **실제 캡처**:

```json
{ "side": "buy", "symbol": "geno", "qty": 2, "price": 44618,
  "gross": 89236, "fee": 178, "cash": 910586, "equity": 999822 }
```

| 필드 | 의미 |
|---|---|
| `price` | **서버가 체결한 가격**. 요청 시점에 프론트가 보던 가격과 다를 수 있다 |
| `gross` | `price × qty` |
| `fee` | 체결금액의 0.2%, **내림**. 매수·매도 양방향 부과 |
| `cash`, `equity` | 체결 후 값 |

> **낙관적 UI 금지.** 가격이 매 tick 바뀌므로 클라이언트가 추정한 체결가는 반드시 어긋난다.
> 화면은 이 응답의 `price`/`fee`/`cash` 로만 갱신한다.

오류: `400 insufficient_cash` · `400 insufficient_shares` · `400 bad_quantity` ·
`400 unknown_symbol` · `400 bad_side` · `423 locked` · `404 no_session`

### `POST /api/analyze` — AI 분석 (라운드당 5회)

```json
{ "session_id": "…", "news_id": 0 }
```

응답 `200` — **실제 캡처**:

```json
{ "news_id": 0, "strength": "none", "label": "무영향",
  "commentary": "이미 알려진 내용의 재인용이거나 규모가 미미하다. 판정: 무영향. …",
  "ramp_remaining": 0, "already_priced_in": true,
  "offline": true, "analyses_left": 4 }
```

| 필드 | 의미 |
|---|---|
| `strength` | 5단계 판정. 아래 표 |
| `label` | 그 판정의 한국어 라벨. 그대로 표시하면 된다 |
| `commentary` | 애널리스트 어투 해설 2~3문장 |
| `ramp_remaining` | **기회가 남은 초.** 0 이면 이미 다 반영됐다 |
| `already_priced_in` | `ramp_remaining == 0` 과 같다 |
| `offline` | `true` 면 Claude 가 아니라 로컬 문장이다. 배지로 표시할 수 있다 |
| `analyses_left` | 차감 **후** 잔여 횟수 |

| `strength` | `label` | 뜻 |
|---|---|---|
| `up_strong` | 강한 상승 | 진짜 큰 호재 |
| `up_weak` | 약한 상승 | 방향은 맞지만 작다 |
| `none` | 무영향 | 과장 기사. 수수료만 날린다 |
| `down_weak` | 약한 하락 | |
| `down_strong` | 강한 하락 | 호재로 읽혔다면 함정이다 |

> **원시 임팩트 수치는 절대 응답에 실리지 않는다.** 등급과 남은 시간만 나간다.
> 소수점 계산 게임이 되지 않게 하려는 의도적 설계다.

호출은 몇 초 걸릴 수 있다(실제 Claude 호출). **그동안 시장은 계속 움직인다** — 기다리는
시간이 분석의 실질 비용이다. 로딩 중에도 폴링을 멈추지 말 것.

오류: `400 no_analyses_left` · `404 no_news`(없거나 아직 공개 전) · `423 locked` · `404 no_session`

### `POST /api/company-analysis` — 기업분석 (라운드당 2회)

```json
{ "session_id": "…", "symbol": "geno" }
```

응답 `200` — **실제 캡처**:

```json
{
  "symbol": "geno", "name": "제노셀",
  "fair_value": 39216, "current_price": 47909,
  "gap_pct": 22.2, "valuation": "overvalued", "label": "고평가",
  "financials": {
    "quarter": "2024Q1", "revenue": 81200000000,
    "operating_income": 16500000000, "net_income": 12800000000,
    "eps": 1032, "per": 46.4, "debt_ratio": 40.0
  },
  "commentary": "제노셀 은 바이오 섹터 기준 배수를 웃돈다. 판정: 고평가. …",
  "offline": true, "company_analyses_left": 1
}
```

`AI 분석` 과 대칭이다. 서버가 쥔 확정 판정을 사고, Claude 는 근거만 풀어쓴다.
**호출 중에도 시장은 계속 흐른다** — 락을 쥐지 않는다.

`gap_pct` 는 `(current_price − fair_value) / fair_value × 100` 이다. 양수가 고평가.

| gap_pct | valuation | label |
|---|---|---|
| ≥ +25 | `severely_overvalued` | 심각한 고평가 |
| +25 ~ +10 | `overvalued` | 고평가 |
| +10 ~ −10 | `fair` | 적정 |
| −10 ~ −25 | `undervalued` | 저평가 |
| ≤ −25 | `severely_undervalued` | 심각한 저평가 |

**같은 종목을 다시 부르면 횟수가 안 깎인다.** 재무는 라운드 내내 바뀌지 않으므로
같은 값을 두 번 파는 것은 함정이다. 응답은 동일하고 `company_analyses_left` 도 그대로다.

`per` 은 적자 분기에 `null` 이다. 그 경우 적정가는 PER 이 아니라 매출 기준(PSR)으로 냈다.

### `POST /api/grind` — 노가다 (언제든)

```json
{ "session_id": "…" }
```

응답 `200` — **실제 캡처**: `{ "payout": 200000, "lock_remaining": 120, "grind_count": 1 }`

- 120초간 매매와 분석이 모두 잠긴다. **시장은 그동안 계속 움직인다.**
- 보수는 회차마다 3/5 로 준다: 200,000 → 120,000 → 72,000 → 43,200 → 25,920 …
- 횟수 제한은 없다. 공식적인 게임오버도 없다.
- **지급은 잠금이 끝난 뒤 다음 요청 때** 이뤄진다. 폴링하면 `cash` 가 올라간다.

오류: `423 locked`(이미 잠김) · `404 no_session`

> **파산은 전제가 아니다.** 평소에도 누를 수 있다. 보수가 3/5 씩 줄고 120초 동안 아무것도
> 못 하므로 스스로 균형이 잡힌다 — 부자일 때는 그동안 놓치는 램프가 보수보다 비싸고,
> 가난할 때만 남는 장사다. 전부 뽑아도 라운드당 **498,909원**이라 목표(3배)에는 노가다만으로
> 닿지 못한다.
>
> 파산 상태에서도 **매매와 분석은 여전히 가능하다.** 노가다는 막힌 길이 아니라 추가 선택지다.
> 그래서 파산 판정(`bankrupt: true`)은 노가다 버튼을 여는 신호일 뿐, 다른 UI 를 잠그지 않는다.

## 4. 상태 스냅샷

`POST /api/game`, `GET /api/state`, `POST /api/next-round` 가 모두 이 모양을 돌려준다.

| 필드 | 타입 | 의미 |
|---|---|---|
| `session_id` | string | |
| `tick` | int | 게임 시작 후 경과 초 |
| `round_no` | int | 1부터 |
| `cash` | int | 현금 |
| `equity` | int | **총자산** = 현금 + 보유 평가액 |
| `target` | int | 이번 라운드 목표 자산 |
| `round_start_equity` | int | 이번 라운드 시작 자산. 진행바 계산에 쓴다 |
| `analyses_left` | int | 남은 분석 횟수 (0~5) |
| `company_analyses_left` | int | 남은 **기업분석** 횟수 (0~2). 별개 풀이다 |
| `ai` | array | 리더보드. 아래 |
| `trades` | array | 체결 피드. `trades_since` 로 걸러진다. 아래 |
| `bankrupt` | bool | `equity < 100000`. 노가다 버튼을 여는 신호 |
| `locked` | bool | 노가다 잠금 중 |
| `lock_remaining` | int | 남은 잠금 초 (올림). 카운트다운은 **이 값**을 쓴다 |
| `grind_count` | int | 이번 라운드의 노가다 횟수 |
| `goal_reached` | bool | `equity >= target` |
| `stocks` | array | 아래 |
| `news` | array | 아래. `since` 로 걸러진다 |
| `news_total` | int | 미공개 포함 전체 기사 수 |

### `stocks[]`

```json
{ "symbol": "hanbit", "name": "한빛솔리드", "sector": "반도체",
  "price": 91117, "change_pct": 0.0, "held": 0,
  "fundamentals_analyzed": false,
  "avg_cost": null, "history": [90980, 91044, 91117],
  "volume": 116, "volume_avg": 116 }
```

`change_pct` 는 **시작가 대비** 등락률이다(직전 tick 대비가 아니다). `held` 는 보유 수량.

**시작가는 판마다 다르다.** 각 종목은 그 판의 적정가 대비 −30%~+30% 사이 랜덤 위치에서
출발한다. 매판 어느 종목이 고평가인지가 달라진다.

`fundamentals_analyzed` 는 이 라운드에 그 종목의 적정가를 샀는지다. 뉴스의 `analyzed` 와
**이름이 다르다** — 둘은 별개 자원이다.

`avg_cost` 는 **수수료를 포함한** 취득 단가(내림)다. **안 들고 있으면 `null` 이다** — 0 을
주면 프론트가 그걸 평단으로 믿고 틀린 손익을 그린다. 일부를 팔아도 남은 주식의 단가는
그대로고, 전량 매도하면 다시 `null` 이 된다.

`history` 는 최근 **60틱**의 가격이다. 오래된 것이 앞이고 **마지막 값이 `price` 와 같다.**
서버가 들고 있으므로 **새로고침해도 차트가 남는다.** 탭을 오래 비웠다 돌아와도 길이는
60을 넘지 않는다.

`volume` 은 최근 60틱의 체결 수량(매수·매도 합)이고, `volume_avg` 는 그때까지의 구간
평균이다. *"평소의 5배"* 를 프론트가 계산하는 기준이다.

### `ai[]`

```json
{ "id": "kang", "name": "강사원", "cash": 798017, "equity": 1055219, "rank": 1 }
```

**보유 종목은 공개하지 않는다.** 체결 피드를 성실히 읽으면 재구성할 수 있고, 그건 주의
깊은 플레이어의 정당한 우위다.

순위는 **총자산(`equity`) 기준**이다. 동점이면 명단 순서로 가른다 — 임의로 흔들리면
리더보드가 매 폴링마다 요동친다.

### `trades[]`

```json
{ "seq": 1, "tick": 15, "actor": "강사원", "symbol": "geno", "name": "제노셀",
  "side": "buy", "qty": 15, "price": 32442 }
```

플레이어 자신의 체결도 `actor: "you"` 로 함께 흐른다.

> **이게 거래량보다 강한 단서다.** 김부장이 매번 낚이는 성향이라면, 어떤 기사에
> **김부장만** 들어간 것은 함정의 신호다. 숫자가 아니라 **신원**을 읽는 것이고, 몇 판
> 하면서 배우는 지식이 된다.

### `news[]`

```json
{ "news_id": 0, "symbol": "pixel", "name": "픽셀로그", "sector": "게임",
  "headline": "픽셀로그 생산 라인 일시 중단… 출하 지연 우려",
  "body": "업계는 게임 업황 조정 국면의 일부로 보고 있으나 …",
  "age_seconds": 188, "analyzed": false, "commentary": "", "offline": true }
```

| 필드 | 의미 |
|---|---|
| `age_seconds` | 이 기사가 뜬 지 몇 초 됐는지 |
| `analyzed` | 분석을 이미 썼는지 |
| `commentary` | 분석 전에는 `""`. 분석 후에는 해설이 채워진다 |
| `offline` | 로컬 템플릿으로 만들어진 기사인지 |

> **`impact`, `kind`, `ramp_seconds`, `publish_tick` 은 어떤 응답에도 없다.** 게임의 정답이므로
> 서버 밖으로 나가지 않는다. 프론트가 이 값들을 얻을 방법은 분석을 지불하는 것뿐이다.

## 6. API 가 주지 않는 것 — 프론트가 계산해야 한다

이 절이 프론트 계획의 출발점이다.

| 필요한 것 | 왜 없나 | 프론트가 할 일 |
|---|---|---|
| **최대 매수 수량** | 서버에 엔드포인트 없음 | `cash`, `price`, 수수료 0.2% 로 계산. 서버 판정과 어긋나지 않으려면 내림을 맞춰야 한다 |
| **주문 금액·예상 수수료** | 표시용이라 서버가 안 줌 | `price × qty` 와 그 0.2% 내림 |
| **평가손익** | 표시용 산술이라 서버가 안 줌 | `avg_cost` 와 `price`, `held` 로 계산 |
| **뉴스 램프 구간** | `ramp_seconds` 는 정답이라 비공개 | `age_seconds` 로 시작점만 표시. **끝점은 분석을 사야 안다** |
| **적정가와 밸류에이션** | 임팩트와 같은 등급의 정답 | 기업분석 응답을 직접 들고 있어야 한다. **새로고침하면 사라진다** |

**가격 이력과 평단은 이 목록에서 빠졌다.** 서버가 메모리에 들고 있다 — §4 의 `history` 와
`avg_cost`. 새로고침하면 차트와 평단이 사라지던 문제가 이걸로 해소된다. DB 는 여전히 없다.

램프 구간 항목은 게임 디자인상 의미가 있다 — 분석은 판정만 사는 게 아니라 **기회의 남은
창까지** 사는 것이다. 미분석 기사에는 점선 마커만, 분석한 기사에는 램프 구간까지 그린다.

## 7. 알려진 거친 모서리

구현 중 발견했고 의도적으로 남긴 것들이다. 프론트 작업 전에 판단이 필요하면 알려달라.

1. **소수 `qty`** 는 `422` 와 다른 본문 모양을 받는다. 정수 스테퍼를 쓰면 발생하지 않는다.
2. **천문학적으로 큰 `qty`**(약 10³⁰⁹ 이상)는 내부 float 변환에서 넘쳐 원시 `500` 이 된다.
   데이터 손상은 없다. 프론트에서 상한을 두면 도달하지 않는다.
3. **30분 조용한 세션은 버려진다.** 새 게임을 만들 때 쓸어낸다 — 폴링 중인 판은
   수명이 갱신되므로 영향받지 않는다. 체결 피드도 최근 500건까지만 남는다.
4. **서버를 재시작하면 모든 게임이 사라진다.** 세션이 메모리 딕셔너리 하나에 있고 DB 가
   없다. 가격 이력과 평단도 그 안에 있으므로 함께 사라진다 — 새로고침은 견디지만
   재시작은 못 견딘다.

## 8. 백엔드 구성 — 기능 11개

| | 모듈 | 하는 일 |
|---|---|---|
| 1 | `engine` (79줄) | **가격 시뮬레이션.** 종목별 랜덤워크 + 뉴스 임팩트를 램프로 반영. 타이머 없이 요청 시점에 증분 계산 |
| 2 | `scenario` (69줄) | **낚시 뉴스 설계.** 각 기사의 숨은 임팩트·램프 길이·등장 시각을 결정. 정직/과장/역방향 비율 배분 |
| 3 | `news` + `fallback` (187줄) | **기사 문장 생성.** Claude 에 톤만 주고 문장을 받음. 실패하면 템플릿 |
| 4 | `analysis` (73줄) | **AI 분석.** 확정된 판정을 Claude 가 해설로 풀어씀. 라운드당 5회 |
| 5 | `session` (198줄) | **거래.** 매수/매도, 양방향 0.2% 수수료, 현금·보유 검증 |
| 6 | `session` | **파산과 노가다.** 총자산 10만 미만 판정, 120초 잠금, 3/5씩 줄어드는 보수 |
| 7 | `session` + `main` | **라운드 전환.** 목표 3배 달성 시 다음 라운드, 분석 5회 리필. 새 분기 실적으로 적정가 재계산 |
| 8 | `fundamentals` | **적정가.** 커밋된 재무 스냅샷에서 섹터 배수로 산출. 흑자는 PER, 적자는 PSR |
| 9 | `company_analysis` | **기업분석.** 확정된 밸류에이션 등급을 Claude 가 해설. 라운드당 2회 |
| 10 | `participants` | **AI 참가자.** 명단 9명, 결정론적 매매 정책, 체결 생성 |
| 11 | `engine` + `session` | **주문 흐름과 거래량.** 감쇠하는 가격 충격, 체결 피드 |

여기에 `main` 이 세션 저장소·동시성 락·뉴스 자동 보충을 얹는다.

`scripts/fetch_fundamentals.py` 가 DART 오픈API 로 스냅샷을 갱신한다. **서버는 이 파일을
임포트하지 않는다** — 재무는 분기에 한 번 바뀌고 한 판은 몇 분이라, 런타임 호출은
구조적으로 이유가 없다. 덕분에 테스트가 네트워크를 한 번도 타지 않는다.

### 무게 중심은 2번과 4번의 관계다

거래는 이 백엔드에서 가장 단순한 부분이다. 알맹이는 뉴스와 분석이 **정반대 방향으로**
작동한다는 점이고, 그 비대칭이 게임이 성립하는 조건이다.

- `scenario` 가 각 기사의 **정답을 미리 확정**해 서버 안에만 둔다.
- `news` 는 Claude 에게 **표면 톤만** 준다. `kind` 나 `impact` 가 프롬프트에 새면 Claude 가
  함정 기사에 무의식적으로 유보적 표현을 흘려, 플레이어가 읽기만으로 낚시를 알아챈다.
- `analysis` 는 반대로 **정답을 전부** 주고 근거만 설명하게 한다. Claude 가 다시 판정하면
  플레이어에게 보이는 판정과 가격 엔진의 실제 동작이 어긋난다.

그래서 §06 에서 프론트가 직접 계산해야 하는 목록이 나온다 — 서버가 인색해서가 아니라,
정답을 내보내지 않으려면 그 파생값들도 내보낼 수 없기 때문이다.

### 축이 둘이다

`fundamentals` 가 더해지면서 플레이어가 답해야 할 질문이 두 개가 됐다.

| 축 | 묻는 것 | 사는 방법 | 가격에 닿는 경로 |
|---|---|---|---|
| 뉴스 | 이 기사가 진짜인가 | `AI 분석` 5회 | `scenario` → 임팩트 → 램프 |
| 펀더멘털 | 이 회사가 애초에 좋은가 | `기업분석` 2회 | 재무 → 적정가 → 평균회귀 앵커 |

둘은 직교한다. **호재가 진짜여도 고평가 종목이면 램프가 끝나자마자 앵커가 끌어내린다.**
앵커는 뉴스보다 한참 약하게(반감기 약 3분) 잡혀 있다 — 이기면 뉴스가 장식이 되고
AI 분석 5회의 희소성이 무너진다.

### 그래프 그리기는 백엔드에 없다

백엔드 코드에 `chart`·`graph`·`sparkline` 이라는 단어는 한 번도 나오지 않는다. 그림은 전부
프론트가 SVG 로 그리고, **그릴 데이터조차 서버에 없다** — 가격 상태는 종목별 "현재 누적
수익률" 하나뿐이고 과거 tick 값은 어디에도 보관되지 않는다. §06 참조.

## 10. 무엇이 달라지나

한 문장으로: **혼자 목표를 채우는 게임에서, 아홉 명과 경주하는 게임이 된다.**

| | v1 | v2 | 지금 |
|---|---|---|---|
| 목표 판정 | **총자산**이 목표 도달 | **현금**이 목표 도달 | **미구현** |
| 종료 | 목표 도달 시 다음 라운드 | **누구든 먼저 도달하면 즉시 종료** | **미구현** |
| 경쟁자 | 없음 | AI 참가자 1~9명 | ✅ |
| 가격을 움직이는 것 | 뉴스 + 노이즈 | 뉴스 + 노이즈 **+ 주문 흐름** | ✅ |
| 거래량 | 없음 | AI와 플레이어 체결의 합계 | ✅ |
| 분석이 약속하는 것 | 결과까지 확실 | **재료 판정은 확실, 결과는 아님** | ✅ |

### 왜 목표를 현금으로 바꾸나

v1 에는 **팔 이유가 거의 없다.** 사서 오르면 총자산이 오르고 그걸로 이긴다. 매도는 사실상
장식이다. 현금 기준으로 바꾸면 *"언제 익절하나"* 라는 결정이 생긴다 — 램프를 더 타면
이익이 크지만 진척은 0이고, 팔면 진척이 쌓이지만 남은 상승을 놓친다.

### 왜 분석의 약속이 바뀌나

주문 흐름이 가격을 움직이면, 뉴스가 진짜 호재여도 다른 참가자들이 팔아서 주가가 내려갈 수
있다. 뉴스 **자신의 기여분**은 여전히 정확히 판정대로다 — 달라지는 것은 결과가 그것만으로
결정되지 않는다는 점이다. 실제 시장이 그렇고, **옳게 고르고도 질 수 있다**는 경험이 생긴다.

## 11. API 변경

### 변경 · `POST /api/game`

요청 본문이 생긴다.

```json
{ "ai_count": 5 }
```

`1`~`9`, 기본 `5`. 범위 밖이면 `400 bad_ai_count`.

> AI 수는 난이도 다이얼이기도 하다. 많을수록 경쟁이 빡세지고, **거래량이 늘어 주문 흐름이
> 가격에 더 크게 작용한다.**

### 변경 · 상태 스냅샷에 추가되는 필드

| 필드 | 타입 | 의미 |
|---|---|---|
| `status` | string | `"running"` \| `"finished"` |
| `ai` | array | 리더보드. `{ id, name, cash, rank }` |
| `trades` | array | 체결 피드. `trades_since` 로 걸러진다 |
| `ranking` | array \| null | 종료 시에만. `{ rank, name, cash, is_player }` |
| `winner` | string \| null | 종료 시 승자 이름. 플레이어면 `"you"` |
| `stocks[].volume` | int | 최근 구간 체결 수량 |

**의미가 바뀌는 기존 필드**

`equity`, `cash`, `bankrupt` 는 그대로 남는다. **파산은 여전히 총자산 기준**이다 — 이유는 §12.

### 새 자료 · `trades[]`

{ "seq": 41, "tick": 137, "actor": "김부장",

플레이어 자신의 체결도 `actor: "you"` 로 함께 흐른다.

|---|---|---|
| `bad_ai_count` | 400 | `ai_count` 가 1~9 밖 |
| `game_finished` | 400 | 종료된 게임에 매매·분석·노가다 시도 |

### 미정 · `POST /api/next-round`

**이 엔드포인트의 운명이 아직 안 정해졌다.** 누구든 목표에 닿으면 게임이 끝난다면
라운드 전환이 낄 자리가 없다. 두 갈래다:

1. **한 판 = 한 경주.** 라운드 개념을 없애고 `next-round` 를 제거한다. 분석 5회는 게임당 5회.
2. **경주를 여러 판 이어서.** 각 경주가 한 라운드이고, 끝나면 전원이 그 결과를 안고 다음
   경주로 간다. `next-round` 가 남는다.

§13 에 착수 전 결정 사항으로 올려둔다.

## 12. 규칙 상세

### 종료와 순위

- 참가자 **누구든** `cash >= target` 에 닿는 순간 게임이 끝난다.
- 전원의 보유 주식이 **그 시점 가격으로 강제 매도**된다. **수수료도 부과된다** — 미리 팔아둔
  사람이 유리해야 익절 판단에 의미가 생긴다.
- 최종 현금으로 순위를 매긴다. 목표에 먼저 닿은 사람이 1위지만, **2위 이하는 남은 현금 순**이다.

### 목표는 현금, 파산은 총자산 — 잣대를 통일하지 않는다

두 질문이 다르기 때문이다.

- 목표는 *"레이스를 얼마나 달렸나"* → **팔아서 확정한 것만** 센다.
- 파산은 *"아직 게임을 할 수 있나"* → 주식은 팔면 현금이 되므로 **세야 한다.**

현금 기준으로 파산을 재면 300만어치 주식을 들고도 파산 판정이 나 노가다 버튼이 열린다.
명백히 틀렸다. **파산선은 총자산 100,000원 그대로.**

화면에는 `현금 / 평가액`을 나란히 보여줘야 플레이어가 자기 상태를 이해한다.

### 노가다가 훨씬 가혹해진다

v1 은 시간 무제한이라 120초 잠금이 가벼운 벌칙이었다. v2 는 경주다 — 한 판이 6분이면
**잠금이 경주의 1/3**이고 그동안 경쟁자들은 계속 달린다. 사실상 패배 선고에 가깝다.

**의도된 것으로 둔다.** 파산이 진짜 재앙이어야 매매에 무게가 실린다. 다만 프론트는 버튼을
누르기 전에 *"지금 누르면 사실상 집니다"* 를 알려야 한다.

### AI 는 LLM 이 아니다 — 결정론 때문이다

서버에는 타이머가 없다. 탭을 30분 비웠다 돌아오면 1,800 tick 이 한 요청에서 진행된다.
AI 매매도 같은 방식으로 계산되므로 **(시드, tick, 뉴스)의 결정론적 함수**여야 한다.
LLM 호출은 결정론적이지 않고 재생할 수도 없으며, 따라잡기 요청에서 1,800번 부를 수도 없다.

체결 현황만 공개하고 코멘트가 없으므로 **이름과 직함은 정적 목록이면 충분하다.**
LLM 호출은 v1 과 동일하게 뉴스 생성 한 곳뿐이다.

### AI 실력 차 — 파라미터 넷

| 파라미터 | 의미 |
|---|---|
| 통찰력 | 낚시를 꿰뚫어 볼 확률. 0.9 면 고수, 0.2 면 매번 물린다 |
| 반응 속도 | 기사 후 몇 tick 뒤에 움직이나. 빠를수록 램프 초반을 먹는다 |
| 베팅 크기 | 자산의 몇 %를 거나 |
| 익절 규율 | 목표가 현금이니, 언제 파느냐가 곧 실력이다 |

**통찰력이 높은데 익절을 못 하는 AI** 는 계속 옳은 종목을 사면서도 현금이 안 쌓여 순위가
낮다. *"옳게 고르는 것과 이기는 것은 다르다"* 를 가르친다.

### 주문 흐름의 가격 영향 — 두 가지 안전장치

**뉴스가 주역, 주문 흐름은 조역.** 체감상 뉴스 임팩트의 20~30% 진폭. 주문 흐름이 뉴스보다
세면 게임의 축이 뒤집힌다. 이 비율이 새 밸런스 다이얼이다.

**되먹임 감쇠 필수.** AI 가 상승에 반응해 사고 그 매수가 가격을 또 올리면 무한 나선이 된다.
가격 영향에 감쇠를 걸고 모멘텀 추종형 AI 비중을 제한한다.

부수 효과: **플레이어 자신의 주문도 가격을 민다.** 큰 주문일수록 불리하게 체결되는
슬리피지가 자연히 생긴다.

| | 무엇 | 새 코드 | 기존 변경 | 왜 미뤘나 |
|---|---|---|---|---|
| D | **목표 판정 변경** — 현금 기준 | | `session.goal_reached` | `goal_reached`·`target` 의 **의미**가 바뀐다 |

둘은 프론트의 진행바·라운드 전환·목표 판정을 전부 다시 만들게 한다. 그래서 필드
**추가만** 하는 다섯(A·B·C·F·G)을 먼저 넣고, 둘은 프론트와 같이 옮기기로 했다.

### 착수 전 결정 사항

1. **라운드를 유지할 것인가** — §11 미정 항목. 한 판 = 한 경주인지, 경주를 여러 판 잇는지
2. **가격 이력과 평단을 서버가 줄 것인가** — §06 참조. v2 를 손대는 김에 함께 결정하는 것이
   낫다. 지금은 프론트가 들고 있어야 하고 새로고침하면 사라진다
3. **주문 흐름 진폭의 초기값** — 뉴스 임팩트 대비 20~30% 로 시작해 플레이해보며 조정
4. **AI 성향 조합의 초기 구성** — 9명을 어떤 통찰력 분포로 채울지

### 순서

펀더멘털 앵커와 기업분석(1차)은 **끝났다** — §03·§04·§08 이 그 계약이다. 남은 순서는:

**2차 AI 참가자 → 3차 종토방 → 나머지 v2 → 프론트.**

종토방은 **AI 참가자가 쓴다.** 플레이어가 쓰는 진짜 게시판은 DB·계정·영속성이 따라오고,
지금 세션이 전부 메모리에 있으므로 서버 구조가 통째로 바뀐다. AI 가 쓰면 싱글플레이어를
그대로 두고도 *믿을 수 없는 군중* 이라는 층이 생긴다 — 뉴스가 믿을 수 없는 기사인 것과
짝이 맞는다. 그래서 AI 참가자가 종토방보다 먼저다.

프론트를 먼저 만들면 두 번 만들게 된다 — 리더보드, 체결 피드, 현금 기준 진행바, 거래량
막대가 전부 새로 생긴다.
