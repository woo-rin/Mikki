# 모의주식게임 설계

작성일: 2026-09-07

## 1. 개요

AI가 생성한 가짜 뉴스에서 힌트를 얻어, 실시간으로 움직이는 가상 주식시장에 투자하는 싱글플레이 웹 게임.

뉴스 중 일부는 낚시(과장·역방향)이고, 라운드당 5회 제한의 `AI 분석` 버튼만이 진짜와 낚시를 확실히 판별해준다. 파산하면 `노가다` 버튼으로 2분간 조작이 잠긴 채 현금을 얻어 복귀하지만, 회차마다 수익이 줄어든다.

게임의 재미 축은 하나다: **뉴스를 읽고, 다섯 번의 분석을 어디에 쓸지 결정하는 것.**

### 핵심 설계 원칙

1. **정답은 서버에만 있다.** 낚시 뉴스의 실제 임팩트가 클라이언트에 내려가면 F12 한 번으로 게임이 무너진다.
2. **밸런스는 코드가, 문장은 Claude가 소유한다.** 임팩트 수치를 Claude가 정하면 판마다 난이도가 흔들린다.
3. **Claude는 판정자가 아니라 해설자다.** 정답은 뉴스 생성 시점에 확정되고, 분석은 그 정답을 사람 말로 풀어쓰는 일만 한다.
4. **게임은 어떤 경우에도 멈추지 않는다.** Claude 호출 실패는 전부 로컬 폴백으로 흡수한다.

## 2. 게임 규칙

### 종목

가상 기업 6개. 섹터를 흩뜨려 뉴스가 특정 종목을 지목했을 때 "안 들고 있는 종목인데 지금 살까"라는 판단이 생기게 한다.

| 종목 | 섹터 | 시작가 | tick당 변동성 |
|---|---|---|---|
| 한빛솔리드 | 반도체 | 82,000 | 0.30% |
| 제노셀 | 바이오 | 45,000 | 0.40% |
| 성진셀즈 | 2차전지 | 61,000 | 0.30% |
| 픽셀로그 | 게임 | 33,000 | 0.25% |
| 태산건영 | 건설 | 18,500 | 0.15% |
| 아라윙스 | 항공 | 24,000 | 0.20% |

종목명은 실제 상장사와 무관한 가상 기업이다. 구현 시 각 이름이 실제 상장사와 겹치지 않는지 확인하고, 겹치면 변형한다.

### 자금과 목표

- 시드: 1,000,000원
- 라운드 1 목표: 3,000,000원 (라운드 시작 자산의 3배)
- 매매 수수료: 체결 금액의 0.2%, 매수·매도 양방향
- 공매도·레버리지·지정가 주문 없음. 현금 시장가 매수/매도만.

### 시간

- 1 tick = 1초. 가격은 tick마다 갱신된다.
- 프론트는 500ms 간격으로 폴링한다.
- 뉴스는 약 30초 간격(28~32초 균등)으로 등장한다. 등장 시각은 시나리오 생성 시 미리 확정된다.
  (최초 설계는 12~18초였으나 읽을 틈이 없어 넓혔다.)
- 등장한 뉴스는 피드에 계속 쌓이며, 램프가 끝난 뒤에도 분석할 수 있다.
- **시간 제한은 없다.** 라운드는 목표 자산 도달로만 끝난다.

### AI 분석

- 라운드당 5회. 라운드가 넘어가면 5회로 리필된다.
- 시간이 무제한이라 뉴스는 계속 나오지만 분석은 5번뿐이다. 이것이 게임의 유일한 희소 자원이다.
- 분석 중에도 시장은 계속 움직인다. 기다리는 몇 초가 분석의 실질 비용이다.
- 램프가 이미 끝난 뉴스도 분석할 수 있다. 이 경우 남은 램프 시간 대신 **"이미 반영 완료"**를 표시한다 — 늦게 눌렀다는 사실 자체가 정보다.
- 결과는 **방향 + 5단계 강도 + 남은 램프 시간**으로 준다. raw 임팩트 수치는 노출하지 않는다 — 확실한 정답은 유지하면서 소수점 계산 게임으로 변하는 것을 막는다.

강도 등급은 임팩트 절대값(로그수익) 기준으로 매핑한다.

| 등급 | 조건 |
|---|---|
| 강한 상승 / 강한 하락 | `abs(impact) >= 0.08` |
| 약한 상승 / 약한 하락 | `0.02 <= abs(impact) < 0.08` |
| 무영향 | `abs(impact) < 0.02` |

### 파산과 노가다

- **파산 판정**: 총자산(현금 + 보유 평가액)이 100,000원 미만.
- 파산 상태가 되면 `노가다` 버튼이 열린다. **매매와 분석은 여전히 가능하다** — 노가다는 막힌 길이 아니라 추가로 생기는 선택지다. 남은 자금으로 반등을 노리든 노가다로 시드를 받든 플레이어가 고른다.
- 누르면 **120초간** 모든 매매·분석이 잠긴다. 그동안 시장은 계속 움직이고, 그것이 화면에 보인다.
- 잠금이 끝나면 현금이 들어온다: `200,000 × 0.6^(n-1)` (n은 이 라운드의 노가다 회차, 내림).
  - 1회차 200,000 → 2회차 120,000 → 3회차 72,000 → 4회차 43,200 …
- 횟수 제한은 없다. 잠금 시간도 120초 고정이다. 벌칙은 시간이 아니라 **점점 무의미해지는 금액**으로 온다.
- 공식적인 게임오버는 없지만, 노가다에 세 번 기댄 판은 사실상 목표에 닿지 못한다.

### 라운드 진행

목표 자산에 도달하면 다음 라운드가 열린다.

- 다음 라운드 목표 = 라운드 시작 자산 × 3
- 낚시 뉴스 비율이 올라간다: 정직 비율 60% → 50% → 40%, 하한 30%
- 분석 횟수 5회 리필
- 노가다 회차는 라운드마다 초기화된다

## 3. 가격 엔진

### 기본 움직임

각 종목은 drift 0의 로그 랜덤워크다. tick마다 로그가격에 `sigma * noise`를 더한다 (`sigma`는 종목 표의 변동성, `noise`는 표준정규).

뉴스 임팩트가 보통 8~15%이므로 노이즈는 뉴스를 완전히 덮지는 않되 초반 몇 초는 방향을 흐린다. 이 흐림이 있어야 "지금 뛰는 게 뉴스 때문인지 잡음인지" 판단할 여지가 생긴다.

### 뉴스 반영 — 램프

뉴스는 뜬 즉시 반영되지 않는다. 각 뉴스는 `impact`(총 로그수익)와 `ramp_seconds`(15~40)를 갖고, 그 구간에 걸쳐 매 tick `impact / ramp_seconds`씩 로그가격에 더해진다.

```
log_price(sym, T) = log(base(sym))
                  + sum over t<=T of sigma(sym) * noise(sym, t)
                  + sum over active news n of ramp_contribution(n, T)

ramp_contribution(n, T) = n.impact * clamp((T - n.published_tick) / n.ramp_seconds, 0, 1)
```

뉴스가 뜬 순간 들어가면 상승분 전체를, 절반쯤 지나 들어가면 남은 절반만 먹는다. 램프가 끝나면 그 기회는 닫힌다. 이것이 "뉴스에서 힌트를 얻어 투자"의 실제 기계 장치다.

> **구현 주의**: 위 식은 수학적 표현이다. 코드에서 `log(base)` 를 상태로 저장하고
> `floor(exp(log_price))` 로 가격을 내면 부동소수점 왕복에서 1원이 사라진다 —
> 6종목 중 4종목(제노셀 45,000→44,999, 픽셀로그 33,000→32,999, 태산건영 18,500→18,499,
> 아라윙스 24,000→23,999)이 그렇다. 대수적으로 동등하지만 정확한 형태인
> **누적 로그수익만 상태로 저장하고 `floor(시작가 × exp(누적수익))`** 으로 계산한다.
> `exp(0.0)` 이 정확히 `1.0` 이므로 tick 0 에서 여섯 종목 모두 시작가와 일치한다.

### 증분 계산 (타이머 없는 진행)

서버는 백그라운드 타이머를 돌리지 않는다. `GET /api/state` 요청이 올 때 마지막 계산 tick부터 현재 tick까지만 이어서 계산하고, 세션에 `last_tick`과 각 종목의 `log_price`를 갱신한다.

- 500ms 폴링이면 매 요청당 0~1 tick만 계산한다.
- 탭을 비웠다 돌아오면 밀린 tick을 한꺼번에 계산한다. 그 사이 뜬 뉴스는 램프가 이미 끝나 있다 — 자리를 비우면 기회를 놓치는 것이 맞다.
- 같은 세션의 동시 요청이 tick을 두 번 밀지 않도록 세션마다 `asyncio.Lock`을 둔다.

### 낚시의 세 유형

플레이어가 읽는 표면 톤(`surface_tone`)과 실제 임팩트를 어긋나게 만든다.

| 유형 | 표면 vs 실제 | `abs(impact)` (로그수익) | 물렸을 때 |
|---|---|---|---|
| 정직 `honest` | 방향 일치 | 0.05 ~ 0.15 | 진짜 기회 |
| 과장 `exaggerated` | 방향 일치, 임팩트 미미 | 0.00 ~ 0.015 | 수수료만 날림 |
| 역방향 `reversed` | 표면과 반대 방향 | 0.06 ~ 0.12 | 가장 아픔 |

라운드 1 배분: 20건 중 정직 12 / 과장 5 / 역방향 3.

라운드가 오르면 정직 비율이 내려간다(60% -> 50% -> 40%, 하한 30%). **남은 몫은 과장 : 역방향 = 5 : 3으로 쪼갠다.** 반올림으로 합이 어긋나면 정직 건수에서 흡수해 총 건수를 맞춘다.

## 4. Claude 연동

두 호출 모두 `claude-opus-5`를 쓴다 (1M 컨텍스트, 입력 $5 / 출력 $25 per MTok). 구조화 출력은 `client.messages.parse(output_format=<Pydantic 모델>)`로 받아 `response.parsed_output`에서 검증된 객체를 꺼낸다.

### 호출 1 — 뉴스 배치 생성

순서를 뒤집는 것이 핵심이다.

1. `scenario.py`가 먼저 **시나리오 배분표**를 만든다. 20건을 12/5/3으로 쪼개고, 각 건의 종목·표면 톤·임팩트·램프 길이·등장 시각을 규칙과 시드로 확정한다.
2. 그 표를 Claude에 넘겨 **문장만 채우게** 한다.

시나리오 표는 20건을 한 번에 만들지만 **Claude 호출은 두 번으로 쪼갠다** — 앞 5건을 먼저 받아 게임을 열고(약 3초), 뒤 15건은 백그라운드에서 채운다. 20건을 한 번에 기다리면 게임 시작이 10초 넘게 걸린다.

**Claude에게 주는 것과 주지 않는 것**

| 필드 | Claude에 전달 | 이유 |
|---|---|---|
| `symbol`, 섹터 | 전달 | 종목에 맞는 기사를 써야 한다 |
| `surface_tone` | 전달 | 읽히는 톤을 정해줘야 한다 |
| `kind` | **전달하지 않음** | 역방향인 걸 알면 우려 표현을 흘려 문장만으로 낚시가 들통난다 |
| `impact`, `ramp_seconds` | **전달하지 않음** | 위와 같음 |

톤만 알려주면 정직한 호재와 함정 호재의 문장이 원리적으로 구분 불가능해진다. 이것이 낚시 메커니즘이 성립하는 조건이다.

**요청 설정**

- `thinking: {"type": "adaptive"}`, `output_config: {"effort": "medium"}`
- 스트리밍 사용 (출력 약 7K 토큰) — `.stream()` + `.get_final_message()`
- 비용 약 $0.18 / 배치

**풀 보충**: 아직 등장하지 않은 뉴스가 5건 이하로 떨어지면 백그라운드 `asyncio` 태스크로 다음 배치를 생성한다. 새 배치의 등장 시각은 기존 마지막 뉴스 이후로 이어붙인다. 게임 플로우는 막히지 않는다.

### 호출 2 — 분석 해설

분석에는 반대로 전부 알려준다. 기사 전문 + `kind` + 임팩트 등급을 주고 *"기사 안의 표현을 근거로 이 판정을 설명하라"*고 시킨다. Claude가 사후적으로 근거를 찾아내므로 해설이 문장과 어긋나지 않는다.

받는 것은 해설 텍스트 한 덩어리뿐이다. 등급과 남은 램프 시간은 서버가 붙인다. Claude가 등급을 다시 판정하지 않으므로 가격 엔진과 분석 결과가 어긋날 수 없다.

- `thinking: {"type": "adaptive"}`, `output_config: {"effort": "low"}`
- 논스트리밍, `max_tokens` 1024 (출력 약 400 토큰)
- 비용 약 $0.015 / 회

한 판(배치 1 + 분석 5회) 약 **$0.25**.

### 실패 처리

API 키 없음, 네트워크 끊김, 레이트리밋, `stop_reason == "refusal"` — 넷 다 같은 경로로 **로컬 템플릿 생성기**로 떨어진다.

- 뉴스: 헤드라인 템플릿 + 변수(기업명·사건·수치) 조합으로 생성
- 분석: 등급을 그대로 문장에 박아 내보냄
- UI에 "오프라인 해설" 배지를 표시한다
- 폴백도 정답을 주므로 분석 횟수는 정상 차감한다

테스트는 가짜 클라이언트를 주입해 Claude를 한 번도 부르지 않고 전부 돌아간다.

**서버사이드 refusal 폴백을 쓰지 않는 이유**: `claude-opus-5`에는 정책 거절 시 다른 모델로 자동 재시도하는 서버사이드 `fallbacks` 파라미터를 붙이는 것이 기본 권장이지만, 그 파라미터는 `client.beta.messages.create` 경로에 있고 구조화 출력 헬퍼인 `messages.parse()`와 함께 쓰는 조합이 문서화돼 있지 않다. 이 게임은 키 없음·네트워크 장애를 위해 어차피 오프라인 폴백이 필요하므로, refusal도 같은 경로로 합친다. 서버사이드 폴백이 필요해지면 `parse()`를 포기하고 `output_config.format` + 수동 스키마 검증으로 바꾼다.

## 5. 아키텍처

**서버 권위 + 폴링.** FastAPI가 세션 상태와 뉴스 정답을 보유하고, 프론트는 가격만 받는다. 정답이 서버에만 있어 낚시 메커니즘이 유지되고, 노가다 잠금도 서버 시각으로 판정하니 조작할 수 없다.

### 모듈 경계

| 모듈 | 하는 일 | 아는 것 | 모르는 것 |
|---|---|---|---|
| `engine.py` | 상태 + 경과 초 → 가격 | 숫자, 램프 | Claude, HTTP, 세션 저장소 |
| `scenario.py` | 시드 → 시나리오 배분표 | 밸런스 규칙 | Claude, HTTP |
| `session.py` | 매매·파산·노가다·라운드 | 도메인 규칙 | Claude, HTTP |
| `news.py` / `analysis.py` | 문장 확보 | Claude, 폴백 | 게임 규칙 |
| `main.py` | HTTP 입출력 | 라우팅, 상태 코드 | 계산 로직 |

`engine.py`와 `scenario.py`는 순수 로직이라 테스트가 쉽다. Claude를 아는 것은 `news.py`와 `analysis.py` 둘뿐이고, 폴백이 그 안에 갇혀 있어 나머지 코드에 분기가 새지 않는다.

`config.py`가 모든 수치를 소유하므로 밸런스 조정이 한 파일에서 끝난다.

### 엔드포인트

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| POST | `/api/game` | 새 게임. 뉴스 5건만 기다리고(약 3초) 나머지 15건은 백그라운드 |
| GET | `/api/state?since=N` | 폴링 창구. **이 요청이 tick을 증분 진행한다.** 가격·포트폴리오·N 이후 새 뉴스·잠금 상태 |

| POST | `/api/analyze` | `{news_id}` — 해설 반환, 잔여 횟수 차감 |

- 스파크라인과 가격 차트는 인라인 SVG로 직접 그린다. 차트 라이브러리 없음.

## 6. 에러 처리

| 상황 | 처리 |
|---|---|
| Claude 실패 (키·네트워크·레이트리밋·refusal) | 로컬 템플릿 폴백. UI에 "오프라인 해설" 배지 |
| 백그라운드 배치 실패 | 풀이 마르면 템플릿 뉴스로 계속 채움 — 게임은 멈추지 않음 |
| 현금 부족 / 보유량 부족 / `qty <= 0` / 없는 종목 | 400 + 사람이 읽는 메시지 → 토스트. 서버가 항상 최종 판정 |
| 노가다 중 매매·분석 시도 | 423 Locked |
| 세션 없음 (서버 재시작) | 404 → "게임이 만료됐습니다, 새로 시작" 화면 |
| 폴링 실패 | 지수 백오프 재시도 + "연결 끊김" 배지. 서버가 lazy 계산하므로 복구되면 자동으로 따라잡음 |

**돈은 정수로 다룬다.** 수량은 주식 수, 현금은 원 단위 정수. 가격만 float이고, 체결·평가액 계산의 반올림은 전부 **내림** 하나로 통일한다. 반올림 방향이 섞이면 총자산이 몇 원씩 어긋나 파산 판정이 흔들린다.

## 7. 테스트

TDD로 진행한다.

**시간과 난수를 주입 가능하게 만드는 것이 테스트 가능성의 전부다.** `engine`과 `session`은 `time.monotonic()`을 직접 부르지 않고 `now`를 인자로 받는다. 그래야 120초 노가다도 `sleep` 없이 테스트되고, 수천 tick 뒤의 상태도 즉시 만들 수 있다. 난수는 세션이 `random.Random(seed)`를 소유하므로, 테스트에서 변동성을 0으로 죽이면 뉴스 램프만 남아 검증이 깔끔해진다.

### test_engine.py

- 노이즈 0에서 램프 끝 가격이 `시작가 * exp(impact)`와 일치
- 1 tick씩 100번 진행한 결과가 100 tick 한 번과 동일 (증분 계산 정합성)
- 변동성 0이고 뉴스가 없으면 가격이 정지
- 램프 중간 시점의 가격이 선형 비율과 일치

### test_scenario.py

- 20건 배분이 12/5/3
- 역방향 뉴스의 `surface_tone`과 `impact` 부호가 반대
- 과장 뉴스의 `abs(impact)`가 0.015 이하
- 같은 시드가 같은 표를 생성
- 라운드가 오르면 정직 비율이 내려가고 30% 아래로는 내려가지 않음
- 정직 비율이 내려갈 때 남은 몫이 과장 : 역방향 = 5 : 3으로 쪼개지고, 세 유형의 합이 항상 총 건수와 일치

### test_session.py

- 수수료가 매수·매도 양방향으로 차감
- 현금 부족 매수가 거부
- 보유량 부족 매도가 거부
- 총자산이 100,000원 미만이면 노가다가 열리고, **그 상태에서도 매매·분석이 거부되지 않음**
- 노가다 수익이 회차마다 0.6배 (200,000 → 120,000 → 72,000)
- 노가다 중 매매·분석이 잠김, 120초 후 해제
- 분석 6회차가 거부
- 목표 도달 시 다음 라운드가 열리고 분석 횟수가 5회로 리필, 노가다 회차 초기화

### test_news.py

- 실패를 주입한 가짜 클라이언트로 템플릿 폴백이 유효한 뉴스를 반환
- 폴백 뉴스가 시나리오 표의 `symbol`·`surface_tone`과 일치
- **Claude를 한 번도 부르지 않는다**

### API 흐름

`TestClient`로 게임 시작 → 매매 → 상태 조회 한 개.
