# 경주 설계 — 현금 목표와 게임 종료 (D·E)

작성일: 2026-09-15 · 대상: v2 의 마지막 둘 · 선행: [AI 참가자](2026-09-14-ai-participants-design.md)

## 1. 왜 지금인가

AI 참가자 9명을 만들었는데 **이길 방법이 없다.**

리더보드에 순위가 뜨고, 김부장이 함정에 물리는 것도 보이고, 체결 피드도 흐른다. 그런데 게임이 끝나지 않는다. `goal_reached` 는 여전히 *내 총자산*만 보고, 도달하면 다음 라운드로 넘어갈 뿐이다. 경쟁자가 먼저 도달해도 아무 일도 일어나지 않는다.

`api.md` §10 은 v2 를 이렇게 요약한다 — *"혼자 목표를 채우는 게임에서, 아홉 명과 경주하는 게임이 된다."* **지금은 그 문장의 절반만 되어 있다.** D 와 E 가 나머지 절반이다.

## 2. 목표가 현금이 된다 (D)

```
goal_reached :  equity >= target  →  cash >= target
target       :  시드의 3배 = 3,000,000 (고정)
```

**파산은 여전히 총자산 기준이다.** 두 질문이 다르기 때문이다 (`api.md` §12).

| | 묻는 것 | 재는 것 |
|---|---|---|
| 목표 | 레이스를 얼마나 달렸나 | **팔아서 확정한 것만** |
| 파산 | 아직 게임을 할 수 있나 | 주식은 팔면 현금이 되므로 **함께** |

현금으로 파산을 재면 300만어치 주식을 들고도 파산 판정이 나 노가다 버튼이 열린다. 명백히 틀렸다. **파산선은 총자산 100,000원 그대로.**

### 이것이 매도에 의미를 준다

지금은 **팔 이유가 거의 없다.** 사서 오르면 총자산이 오르고 그걸로 이긴다. 매도는 장식이다.

현금 기준이면 *"언제 익절하나"* 가 생긴다 — 램프를 더 타면 이익이 크지만 진척은 0 이고, 팔면 진척이 쌓이지만 남은 상승을 놓친다.

그리고 **한실장(통찰력 2위, 익절선 60%)** 이 비로소 의미를 갖는다. 다 맞히는데 안 팔아 현금이 안 쌓이고, 그래서 진다. §12 의 *"옳게 고르는 것과 이기는 것은 다르다"* 가 순위표에 나타난다.

## 3. 누구든 먼저 닿으면 끝난다 (E)

플레이어든 AI 든 `cash >= target` 이 되는 순간:

1. **전원의 보유 주식을 그 시점 가격으로 강제 매도한다. 수수료도 부과한다** — 미리 팔아둔 사람이 유리해야 익절 판단에 의미가 생긴다.
2. 최종 현금으로 순위를 매긴다. **목표에 먼저 닿은 사람이 1위**, 2위 이하는 남은 현금 순.
3. `status` 가 `"finished"` 가 되고 **tick 이 멈춘다.**

종료 후 매매·분석·기업분석·노가다는 `400 game_finished`. `GET /api/state` 는 계속 된다 — 결과를 봐야 한다.

### 순서가 중요하다

1. 누군가 `cash >= target` 을 넘는다 → **그 사람이 승자다** (강제 매도 전에 확정한다)
2. 전원 강제 매도
3. 승자를 1위에 두고, 나머지를 매도 후 현금으로 줄 세운다

**승자의 최종 현금이 2위보다 적을 수 있다.** 목표선을 막 넘은 사람과, 주식을 잔뜩 들고 있다가 강제 매도로 큰 현금을 쥔 사람이 있을 때 그렇다. 놀랍지만 **의도한 것이다** — 목표는 *먼저 확정한 사람*의 것이고, 그래서 익절을 미루는 전략에 대가가 있다. 화면은 승자를 순위가 아니라 **"먼저 도달"** 로 설명해야 한다.

### 판정 시점

목표 도달은 **tick 루프 안에서** 검사한다. AI 가 매도해 현금이 목표를 넘는 순간이 그 tick 이기 때문이다. 플레이어의 매도는 `POST /api/trade` 직후에 검사한다.

한 tick 안에서 둘 이상이 동시에 넘으면 **명단 순서**로 가른다 — 플레이어가 먼저다. 임의로 흔들리면 같은 시드가 다른 결과를 낸다.

## 4. 라운드가 사라진다

| 지우는 것 | 왜 |
|---|---|
| `POST /api/next-round` | 누가 이겼는데 다음 라운드로 갈 자리가 없다 |
| `round_start_equity` | 진행바가 `cash / target` 이 되므로 기준점이 필요 없다 |
| `session.advance_round` | 리필·재앵커·grind 리셋이 전부 라운드 개념이었다 |

**분석 5회와 기업분석 2회는 게임당 횟수가 된다.** 리필이 없다.

노가다의 `grind_count` 도 리셋되지 않아 감쇠가 끝까지 간다. 한 경주가 6분쯤인데 120초 잠금이면 **경주의 1/3** 이라, §12 가 말한 *"사실상 패배 선고"* 가 그대로 성립한다. **의도한 것이다.**

### `round_no` 만 잠시 남긴다

프론트가 상단 바에 `R{round_no}` 를 그린다. 백엔드가 먼저 나가면 `Rundefined` 가 된다. **`round_no: 1` 을 상수로 남겨** 프론트가 깨지지 않게 하고, 프론트 전환 때 함께 지운다.

이것은 **임시 호환이고 기한이 있다.** §9 의 순서를 따른다.

## 5. 분기를 판 시작 때 고른다

라운드가 사라지면 *"라운드 N = N분기"* 도 갈 곳이 없다. 대신 게임을 시작할 때 4개 분기 중 하나를 `rng` 로 뽑는다.

```python
fundamentals.fair_values(round_no)  →  fundamentals.fair_values(quarter_index)
quarter_of(snapshot, symbol, round_no)  →  quarter_of(snapshot, symbol, index)
```

1차 설계의 핵심 가치는 **"매판 어느 종목이 고평가인지 달라진다"** 였고, 그것은 분기가 아니라 시작 오프셋 ±30% 가 만든다. 분기 전진은 라운드 전환에 의미를 더하는 부수 효과였으므로, 라운드와 함께 판 **사이**로 옮겨간다. 시작 오프셋과 곱해져 다양성은 오히려 늘어난다.

`GameSession` 에 `quarter_index: int` 가 생긴다. 기업분석은 이 값으로 분기를 찾는다.

## 6. 응답

### 달라지는 필드

| 필드 | v1 | 이제 |
|---|---|---|
| `goal_reached` | `equity >= target` | **`cash >= target`** |
| `target` | 라운드 시작 자산의 3배 | **시드의 3배, 고정** |

### 새 필드

```json
{ "status": "running",
  "ranking": null,
  "winner": null }
```

종료되면:

```json
{ "status": "finished",
  "ranking": [
    { "rank": 1, "name": "정소장", "cash": 3010400, "is_player": false },
    { "rank": 2, "name": "나",     "cash": 2180000, "is_player": true }
  ],
  "winner": "정소장" }
```

`winner` 가 플레이어면 `"you"` 다. `ranking` 은 종료 전 `null` 이다.

### 사라지는 필드

`round_start_equity`. `round_no` 는 §4 의 이유로 `1` 고정으로 남는다.

### 새 오류 코드

| 코드 | 상태 | 언제 |
|---|---|---|
| `game_finished` | 400 | 종료된 게임에 매매·분석·기업분석·노가다 시도 |

`goal_not_reached` 는 `next-round` 와 함께 사라진다.

## 7. AI 는 고치지 않는다

AI 의 익절 로직이 **이미 현금을 쌓는 구조다** — 익절선을 넘으면 전량 매도하니 현금이 는다. 현금 목표에서 그대로 작동한다. 파라미터도 정책도 건드리지 않는다.

익절선이 낮은 AI(강사원 8%, 배차장 10%)가 현금을 빨리 쌓고, 높은 AI(한실장 60%, 김부장 40%)가 못 쌓는다. **순위가 통찰력이 아니라 익절 규율을 따라간다** — 설계가 의도한 그림이다.

## 8. 만질 파일

| 파일 | 무엇 |
|---|---|
| `app/session.py` | `goal_reached` 현금 기준, `finish_race`, `advance_round` 제거, `quarter_index` |
| `app/participants.py` | 없음 — AI 는 안 고친다 |
| `app/fundamentals.py` | `fair_values(quarter_index)`, `quarter_of(…, index)` |
| `app/config.py` | `ROUND_TARGET_MULTIPLIER` → `TARGET_MULTIPLIER` 로 개명. 라운드가 없다 |
| `app/main.py` | `status`·`ranking`·`winner`, 종료 검사, `next-round` 제거, `game_finished` 가드 |
| `frontend/` | **§9 에 따라 나중에** |

`session.py` 가 300줄을 넘어간다. 종료·순위는 새 함수로 묶어 플레이어 규칙과 섞이지 않게 한다.

## 9. 순서 — 백엔드 먼저

옆 세션이 종토방으로 프론트를 만지고 있다. 동시에 건드리면 충돌한다.

```
1. 백엔드 — 이 스펙 전부. round_no 는 1 로 남긴다
2. (종토방이 끝나기를 기다린다)
3. 프론트 — 진행바·상단바·종료 화면, 그리고 round_no 제거
```

2 단계 동안 프론트는 **기존 계약으로 계속 돈다.** `goal_reached` 의 의미가 바뀌지만 프론트는 그것을 "다음 라운드" 버튼에만 쓰므로, 버튼이 안 눌리는 정도의 퇴행이다. 곧 지울 버튼이다.

## 10. 테스트

**네트워크도 Claude 도 부르지 않는다.** 기존 286개의 성질을 지킨다.

| | 무엇 | 왜 |
|---|---|---|
| 1 | 현금이 목표에 닿으면 `goal_reached`, 총자산으로는 안 닿는다 | D 의 핵심 |
| 2 | 파산은 여전히 총자산 기준이다 | 잣대를 통일하지 않는다 |
| 3 | AI 가 먼저 닿으면 게임이 끝난다 | E 의 핵심 |
| 4 | 플레이어가 먼저 닿아도 끝난다 | |
| 5 | 종료 시 전원의 주식이 강제 매도된다 | |
| 6 | 강제 매도에도 수수료가 붙는다 | 미리 판 사람이 유리해야 한다 |
| 7 | 승자가 1위, 나머지는 현금 순 | |
| 7b | **승자의 현금이 2위보다 적어도 1위다** | 목표는 먼저 확정한 사람의 것이다 |
| 8 | 동점이면 플레이어가 먼저 | 같은 시드가 같은 결과를 내야 한다 |
| 9 | 종료 후 매매·분석·기업분석·노가다가 전부 `game_finished` | |
| 10 | 종료 후 tick 이 멈춘다 | |
| 11 | 종료 후에도 `GET /api/state` 는 된다 | 결과를 봐야 한다 |
| 12 | `next-round` 가 사라졌다 | |
| 13 | 같은 시드는 같은 분기를 고른다 | 재현 |
| 14 | 분기가 판마다 달라진다 | 다양성이 판 사이로 옮겨갔다 |
| 15 | 증분/일괄 동일성이 종료 판정이 붙어도 유지된다 | 이 서버에서 가장 중요한 불변식 |

15번이 가장 깨지기 쉽다. 종료 검사가 tick 루프 안에 들어가므로, 따라잡기 도중 종료되면 그 시점에서 멈춰야 하고 폴링으로 왔을 때와 같은 결과여야 한다.

## 11. 미룬 것

| 무엇 | 왜 |
|---|---|
| 재시작 버튼 | `POST /api/game` 을 다시 부르면 된다. 프론트 작업에서 다룬다 |
| 전적·통계 | 저장할 곳이 없다. DB 가 없는 한 판 단위 게임이다 |
| AI 성향 재조정 | 현금 목표에서 실제로 어떻게 갈리는지 보고 정한다 |

마지막 항목은 이 변경의 **관찰 대상**이다. 익절 규율이 순위를 지배하게 되는데, 그게 너무 단조로우면 통찰력의 비중을 올려야 한다. 숫자를 고치기 전에 몇 판 돌려본다.
